# 04. 翻訳・翻訳モデル切替 仕様

**親**: [`00-overview.md`](./00-overview.md) ｜ **工程**: ③ 翻訳 ｜ **担当**: backend
**ステージ名**: `translate`

---

## 1. 目的

元言語のセグメント列を日本語へ翻訳する。**複数の LLM モデルを切り替え可能** に保つ（ルール5）。品質優先。

---

## 2. 入出力

| | 内容 |
|---|---|
| 入力 | `transcript.json`（[`03`](./03-transcription-stt.md)） |
| 出力 | `translation.json`（[`09-data-model.md`](./09-data-model.md) §3.3） |
| 実行基盤 | **Ollama**（ローカル HTTP API） |

---

## 3. モデル切替（確定・必須要件）

- 翻訳に使う LLM を **設定で複数から切り替えられる** こと（単一モデルに固定実装しない）。
- Ollama に複数モデルを pull しておき、**モデル名を API パラメータで渡す**。
- 既定候補: **Qwen3 30B級**（Apache 2.0）。対抗: Gemma 3/4、ELYZA、Swallow。
- モデル名・タグはハードコードしない。設定値に切り出し、「導入時に最新タグ確認」コメントを残す。
- 利用可能モデルは `GET /models`（[`01-architecture.md`](./01-architecture.md) §4.1）で UI に提示。`POST /jobs` の `settings.translate.model` で選択。

---

## 4. 翻訳方針

| 項目 | 方針 |
|------|------|
| 対象 | セグメント `text`（元言語）→ 日本語 `target` |
| 文体 | 講義・解説・ドキュメンタリーのナレーション。**です・ます調** の自然な日本語を基本（プロンプトで指定） |
| 文脈 | 直訳でなく、前後の流れを踏まえた訳。文脈保持のため近接セグメントをまとめて投入してよい（下記） |
| 整合 | 入力 `id` と出力 `id` を 1:1 で対応させる（セグメント構造を維持） |

### 4.1 文脈の与え方

- 単発セグメント逐次翻訳は文脈が切れやすい。**前後数セグメントをコンテキストとして与える** か、**チャンク単位で翻訳して id ごとに割り戻す** 方式を採る。
- いずれの方式でも、出力は必ず入力セグメントと 1:1（id 対応）に正規化する。割り戻しに失敗した場合は当該チャンクを再試行。

### 4.2 プロンプト

- システムプロンプトで「日本語ナレーション字幕向けの自然な翻訳」「固有名詞の扱い」「記号・改行を入れない」等を指定。
- プロンプト文面は設定／定数として管理し、モデル差し替え時に調整可能にする。

> **ローカル完結を破らない**: 翻訳は Ollama(HTTP) のみ。クラウド翻訳 API を呼ぶコードを書かない（ルール1）。

---

## 5. 出力

`translation.json`（[`09`](./09-data-model.md) §3.3）。各セグメントに `source`（元文）と `target`（訳文）を持つ。`model` に使用モデル名を記録。

---

## 6. 処理詳細

1. `transcript.json` を読み、コンテキスト付きで Ollama に投入。
2. 進捗はセグメント（またはチャンク）処理数で 0.0〜1.0 を算出し `translate` 進捗として通知。
3. `translation.json` を書き出し、ステージを `done` に。

---

## 7. エラー処理

| 事象 | 対応 |
|------|------|
| Ollama 未起動/接続不可 | `failed`（code: `OLLAMA_UNAVAILABLE`、retryable）。`/health` でも検出 |
| 指定モデル未取得 | `failed`（code: `MODEL_MISSING`）。pull 手順を message に |
| 出力が id 対応に割り戻せない | 当該チャンクを再試行。継続失敗で `failed`（code: `TRANSLATE_MISALIGN`） |

# 要件定義書（v0.6・確定版）

**プロジェクト名**: Reverb（リバーブ）
**作成日**: 2026-06-18
**ステータス**: 確定（数値の微調整のみプロトタイプで実測）
**v0.5からの主な変更**: 旧・未決事項8項目をすべて確定。アーキテクチャを SwiftUI + Pythonバックエンド に決定。翻訳モデルの「切替機能」を機能要件に追加
**コンセプト**: 元の声が日本語になって返ってくる ＝ Reverb（反響）

---

## 1. 目的・背景

外国語の動画ファイルを、外部サービスに頼らず**ローカル環境だけ**で、日本語の**吹き替え音声＋字幕**付きで視聴できるMac用アプリ。クラウドAPIを使わないことでプライバシーを保ち、利用コストをゼロに抑える。品質優先（処理が多少遅くても訳・音声の質を取る）。

---

## 2. コンセプト・全体像

動画ファイルを選択すると、「音声抽出 → 文字起こし → 日本語翻訳 → 字幕整形 → 音声合成 → 尺合わせ・ミックス」を事前一括処理し、その後アプリ内で**日本語吹き替え（ボイスオーバー）＋日本語字幕**で再生する。

音声はボイスオーバー方式。日本語音声を主、元音声をごく小さく残す。処理は事前一括処理型（リアルタイム同時通訳ではない）。

### アーキテクチャ（確定）

2層構成。

- **UI層**: SwiftUI + AVKit のネイティブMacアプリ（動画選択・再生・字幕表示・各種設定）。
- **処理バックエンド層**: Python製の処理パイプライン。Swiftアプリが裏でこのプロセスを起動し、ローカルHTTP等で連携する（サイドカー構成）。
- mlx-whisper等のPythonエコシステムをそのまま活用でき、UIはネイティブにできる「いいとこ取り」構成。

---

## 3. 機能要件

### 3.1 入力
- ローカルの動画ファイルを選択して読み込む（mp4を主対象、将来 mov / mkv 等）

### 3.2 処理パイプライン（事前一括処理）
1. 音声抽出
2. 文字起こし（STT、タイムスタンプ付き）
3. 翻訳（日本語へ）
4. 字幕整形
5. 音声合成（TTS）
6. 尺合わせ・音声ミックス（ボイスオーバー生成）
7. 中間成果物の保存

### 3.3 音声（ボイスオーバー）
- 日本語TTS音声を主、元音声を小音量で残す
- **音量バランス初期値: 日本語100% / 元音声8%**。再生中にスライダーで調整可
- 尺合わせ: speedScale 0.8〜1.3 で調整 → 無音区間で吸収 → 残差は許容

### 3.4 字幕・表示
- 吹き替え音声と並行して日本語字幕を常に表示
- 整形ルール: 1行 全角20字前後 / 最大2行 / 最低表示1.5秒前後 / 長文は意味の切れ目で分割

### 3.5 翻訳モデルの切替（新規）
- 設定で**翻訳に使うLLMモデルを複数から切り替えられる**ようにする
- Ollamaに複数モデルをpullしておき、APIパラメータで選択

### 3.6 再生
- アプリ内プレーヤーで動画＋字幕＋吹き替え音声を同期再生
- 基本操作（再生/一時停止、シーク、音量）

### 3.7 出力
- アプリ内再生のみ。ファイル書き出しはMVPスコープ外

## 5. 対象コンテンツの前提

- 講義・解説・ドキュメンタリー等、話者が少なくナレーション主体の動画
- MVPは単一の声で吹き替え（複数話者の打ち分けはしない）

---

## 6. 技術選定（確定）

> モデルの世代交代は速いため、導入時に最新タグを確認すること。

| 工程 | 採用 | 補足 |
|------|------|------|
| UI | **SwiftUI + AVKit** | ネイティブMacアプリ |
| 処理基盤 | **Python バックエンド**（Swiftからサイドカー起動） | パイプライン全体を統括 |
| 音声抽出・ミックス | **ffmpeg** | Pythonからサブプロセス呼び出し |
| 文字起こし(STT) | **mlx-whisper / large-v3（full）** | 品質優先のため既定はfull。高速が要るときturboに切替可。精度はエンジンでなくモデルで決まる |
| 翻訳(ローカルLLM) | **複数モデル切替（既定候補: Qwen3 30B級）** | Apache 2.0。対抗: Gemma 3/4、ELYZA、Swallow。設定で切替 |
| LLM実行基盤 | **Ollama**（HTTP API） | 複数モデル常駐＆切替が容易 |
| 音声合成(TTS) | **VOICEVOX / 落ち着いた男性の声** | ローカルHTTP API。speedScaleで尺調整。話者は設定で変更可 |

**メモリ運用**: 64GBあるため Whisper + 翻訳LLM + VOICEVOX を同時常駐可能。

## 7. スコープ外（MVPでは「やらない」こと）

- 複数話者の声の打ち分け（単一の声で吹き替える）
- リップシンク
- ファイル書き出し
- リアルタイム（同時通訳的）処理
- 動画のダウンロード機能

---

## 8. 将来拡張（フェーズ2以降）

- 複数話者ごとの声の打ち分け（話者分離 + 複数ボイス）

- 吹き替え・字幕付き動画のファイル書き出し
- 元言語字幕との併記、対訳表示
- 対応形式・対応言語の拡大
- 翻訳結果・字幕の手動編集機能

## 9. 決定事項（旧・未決事項8項目の結論）

| # | 項目 | 確定内容 |
|---|------|----------|
| 1 | 処理時間 | 品質優先。厳密な数値目標は設けず、実測で許容ラインを把握 |
| 2 | 元言語 | 英語ベース＋Whisper自動判定で多言語も受ける |
| 3 | 字幕整形 | 全角20字前後 / 最大2行 / 最低表示1.5秒 / 意味の切れ目で分割 |
| 4 | 尺合わせ | speedScale 0.8〜1.3で調整 → 無音区間で吸収 → 残差許容（テスト時に範囲調整余地） |
| 5 | 音量バランス | 日本語100% / 元音声8%。スライダーで調整可 |
| 6 | VOICEVOX話者 | 落ち着いた男性の声（設定で変更可） |
| 7 | アーキテクチャ | SwiftUI（UI）＋ Pythonバックエンド。STTはmlx-whisper維持 |
| 8 | 翻訳モデル | 複数モデルを切替可能にする（機能要件）。既定候補 Qwen3 30B級 |

> 数値（処理時間・字幕の細部・尺の許容ズレ）はプロトタイプで実測しながら最終調整するが、方針・初期値は上記で確定。
